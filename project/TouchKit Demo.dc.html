Cocoa Touch container controllers in JSX — the tree is the behavior. NavigationStack · SplitView · composable TabBar · Credenza tray · adaptive SideDrawer · A–Z index with haptics.
FRAME
Try: scrub the A–Z rail · swipe a row left · pull down · open a contact → Share Contact for the Credenza tray (heights morph between states) · the clock button opens Activity — fixed panel at 1280px+, overlay sheet below, pushed page on phone · drag from the left edge to go back · Settings swaps composition & table style live · scroll down and the nav bar and tab bar slide away — on Phone 390 the bar stops at the Dynamic Island instead of vanishing.
Composition A — bar persists
<TabView>
  <Tab id="contacts" icon="person">
    <NavigationStack>
      <ContactList />  // pushes slide under the bar
    </NavigationStack>
  </Tab>
  <Tab id="settings">…</Tab>
</TabView>
Each tab owns a NavigationStack, so the bar stays put across pushes — UIKit's tabBarController(navController) shape.
Composition B — bar rides the root view
<NavigationStack>
  <TabView>  // the root screen
    <Tab id="contacts">
      <ContactList />  // a push covers bar + root
    </Tab>
    <Tab id="settings">…</Tab>
  </TabView>
</NavigationStack>
No mode flag — nesting alone decides. Swap trees live in Settings → Composition; app state survives the remount.
