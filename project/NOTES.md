## shadcn MessageScroller semantics (implement in ours)
- Parts: Provider (owns scroll state) / frame / Viewport (scrollable, preserves row on prepend) / Content (role="log", aria-relevant="additions") / Item (row boundary; props messageId, scrollAnchor) / Button (jump to end; `inert` + data-active=false when nothing in its direction).
- Anchoring: when a new item with scrollAnchor=true (usually user msg) is appended, scroll it near the TOP of viewport, keeping `scrollPreviousItemPeek` px (default ~64) of previous item visible above. Reply streams into room below.
- autoScroll: follow live edge ONLY while reader is at bottom; release on wheel/touch/keydown/scrollbar-drag/message-jump; scrollToEnd (or Button) re-engages. data-autoscrolling attr during programmatic scroll.
- defaultScrollPosition: "start" | "end" | "last-anchor" (open saved thread at last user msg; falls back to end if no anchor or turn fits).
- preserveScrollOnPrepend default on (load-history without jumping).
- Hooks: useMessageScroller → {scrollToMessage(id)→bool, scrollToEnd, scrollToStart}; useMessageScrollerVisibility → {currentAnchorId, visibleMessageIds}; useMessageScrollerScrollable → {start, end}.
- Viewport: role="region" aria-label="Messages" tabIndex=0. Items use content-visibility:auto + contain-intrinsic-size.
- Anchor rows: entrance animations OK via transform/opacity only (never height/margin).

## Aug 13 (2nd pass) — list headers + scroll-away chrome + Dynamic Island
- TKStickyCtx (touchkit.jsx top): sticky offset for section headers. ScreenWrap provides `hid ? safeTop : barH`; default 0 so a list in a bare scroller sticks at the top (this was the docs A–Z bug — TKSection had `top:BARH` hardcoded).
- TKList({header, stickyTop, inset}): renders+measures its own sticky header (ResizeObserver) and provides above+headerH to sections. TKSection accepts stickyTop override. Headers transition `top` so they follow the bar.
- chromeStore + useChromeHidden(): screen scroll publishes hide/show (down >5px hides past 0.7*barH, up >5px or near top shows). Nav bar translates -(barH - safeTop) and fades its row; TabBar translateY(100%) unless hideOnScroll={false}; per-screen opt-out `sc.hideChromeOnScroll:false`. Store resets on screen unmount.
- Dynamic Island: `--tk-safe-top` (read via safeTopOf on mount) → barH = safeTop + BARH; bar collapses only to safeTop and an opaque under-island strip counter-translates to stay put. App takes `safeTop` prop (true → 59), sets the var, draws the island capsule. TouchKit Demo passes safe-top=59 on the Phone 390 frame (prop `dynamicIsland`, default true). Contacts jump()/IndexBar top include safeIns.
- Docs: Lists page "Headers: the list works out its own offset"; NavigationStack "Chrome that gets out of the way" + "Dynamic Island"; TabView "Hiding with the scroll".
