# BL UI monorepo conventions

BL UI is an iOS-flavored React component framework: a **core library** and **blocks**, distributed two ways from the same files.

- **Core** (`packages/ui`, published as `@brett_lamy/ui`) — generic, composable parts: theme/tokens, icons, motion, press and util helpers, controls, list primitives, containers (NavigationStack, SplitView, Tabs, Dialog, Sheet, AdaptivePane, Sidebar, Toolbar, IndexBar), the Composer and PencilKit (`PencilKitAnnotator` is the default engine of the Composer's `ImageAnnotator`). Nothing product-specific.
- **Blocks** (`registry/blocks/<slug>`) — full compositions that show how the core fits together and may own complex, product-specific components: the IDE workbench parts (`t3-clone`), the team-chat shell (`discord-clone`), `map-chat`, `delivery-tracking`, `loop-qa`, and so on.
- **Registry** (primary): every core module is its own shadcn item (`registry:ui` / `registry:lib`), with dependencies computed from its imports, so `shadcn add` copies only what a part needs. **npm** (secondary): the same modules, built with `preserveModules` and `'use client'`, for people who want one dependency.

Every component is built **shadcn-style on [UI SDK](https://ui-sdk.dev), styled with Tailwind v4**. UI SDK owns behavior (keyboard, focus, selection, dismissal, popups, drag and drop, ARIA); this library owns the look, the tokens and the iOS-flavored responsive containers. We consume our fork of UI SDK (`vendor/ui-sdk`, a submodule of [BLamy/ui-sdk](https://github.com/BLamy/ui-sdk)) under upstream's names, `@ui-sdk/core` and `@ui-sdk/react`. The behaviors upstream lacks and the kit needs (size classes, page stacks, edge swipes, the platform back, pull to refresh, presence) are this library's own, in `lib/`, built on UI SDK's public API; the fork holds only what can't be built outside UI SDK's core: layer hosts (see "The fork").

## Tech rules

1. **TypeScript ESM** (`.tsx`), React 19. No `window.*` globals, no CDN script injection.
2. **UI SDK base.** Anything interactive is a UI SDK part. Never `react-aria`, `react-aria-components` or `react-resizable-panels`, and never a hand-rolled `role=`, focus trap, roving tabindex, typeahead, outside-press or Escape handler, popup positioning, drag threshold or spring solver when UI SDK has the behavior.
   - **UI SDK ships the component** (`@ui-sdk/react/<name>`: Button, Dialog, Drawer, Popover, Menu, Select, Combobox, Tabs, Toolbar, Tooltip, Toast, Tree, Resizable…): our module wraps its parts with classes and re-exports them. Same composition, same part suffixes (`DialogTrigger`, `DialogContent`, `DialogTitle`, `DialogClose`; a module that keeps our own root name keeps the suffixes: `DropdownMenuTrigger`, `SheetContent`), same props. We add only `variant`/`size` and layout props. The unstyled UI SDK part is imported as `{ Button as SdkButton } from '@ui-sdk/react/button'` (`SdkToggle`, `SdkToolbarButton`…), never re-exported under a kit name.
   - **UI SDK does not ship it** (SplitView, NavigationStack, AdaptivePane, Sidebar, List rows, IndexBar…): it is one primitive, defined once with `definePrimitive` from `@ui-sdk/core` out of UI SDK behaviors, in `lib/<name>-primitive.ts` (framework-free: no React import), and rendered with `createParts` from `@ui-sdk/react/primitive` in `components/<name>.tsx`. Roles go on slots, changes go through `createChange` with a reason, and the definition ends with `agent: { actions }`.
   - **UI SDK has no behavior for it** (size classes, page stacks, edge swipes, the platform back, pull to refresh, presence): it is a generic, framework-free behavior in `lib/` (`lib/size-class.ts`, `lib/stack.ts`, `lib/edge-swipe.ts`, `lib/back.ts`, `lib/pull-to-refresh.ts`; `lib/presence.ts` is its React side), in UI SDK's shape (`bindX(el, options) → cleanup`, `createX(context, options)` for a primitive's `api`), built only on UI SDK's public exports, with its own test, and exported from the barrel. It goes in the fork only when it can't be built on the public API (see "The fork").
   - **The API is UI SDK's.** `onClick` (not `onPress`), `disabled`, `open`/`defaultOpen`/`onOpenChange(open, details)`, `value`/`defaultValue`/`onValueChange(value, details)`, `checked`, `pressed`; `details` carries `reason`, `source` and `cancel()`. Change a part's element with `render`, never `as` or `asChild`; a popup trigger takes the kit's look as `render={<Button … />}`. Drive a component from outside with its controller. Import from entries (`@ui-sdk/react/select`); never `@ui-sdk/core/internal/*`.
   - Where gesture code needs a raw element (canvases, wheels), keep it raw but build it from `bindDrag`, the `@ui-sdk/core/gesture` math and friends, and keep its ARIA and keyboard behavior. Never regress keyboard behavior (arrow keys, Esc, focus order).
3. **shadcn conventions.** Every component takes `className` (and `style`) and merges them last; a UI SDK part's `className` may be a function of its state, so merge with `cx(ours, className)` from `@/lib/utils` (`cn()` for plain elements). Every part spreads its element's props and takes `ref`. `data-slot` comes from UI SDK (`dialog-content`, `split-view-sidebar`): never write one by hand on a part. Variants use `cva` (export the `…Variants` function); compound parts over props, context + hooks over prop drilling.
4. **Tailwind, not inline styles; tokens, not literals.** Style with utility classes. `style={{…}}` is only for values computed at runtime (gesture offsets, measured sizes, animation progress) — prefer the CSS variables UI SDK already writes (`--anchor-width`, `--available-height`, `--transform-origin`, `--drawer-stack`, `--keyboard-inset`…) or feed your own in as variables. Everything themeable comes from `packages/ui/src/tokens.css` (`@theme inline`, the single source; `pnpm tokens` generates `lib/tokens.generated.ts` from it): colors (shadcn's variables plus BL UI's extras such as `text-tertiary-foreground`, `bg-secondary-strong`, `bg-bar`, `text-success`, `border-control-border`), radii (`rounded-ctl|panel|card|sheet`, multiples of `--radius`), the text scale (`text-caption2` … `text-large-title`), shadows (`shadow-hairline`, `-t`, `-b`, `shadow-raised`, `shadow-popover`, `shadow-hud`), heights (`h-row`, `h-toolbar`, `h-bar`) and `font-sans`. Surface palettes are theme scopes (`ThemeScope`) whose values live in `src/theme.css` (core scopes) or a block's own stylesheet. No hex/rgba literals and no new arbitrary `rounded-[…]`, `text-[…px]` or `shadow-[…]`: `node tools/tokens/check.mjs` enforces it against `tools/tokens/allowlist.json` (which only shrinks).
   **State comes from the platform and from UI SDK's attributes.** Hover, press and keyboard focus are the native pseudo-classes: `hover:`, `active:`, `focus-visible:`, `focus-within:` (Tailwind's `hover:` already skips touch). Component state is UI SDK's attributes: `data-open`/`data-closed`, `data-disabled`, `data-pressed` (a toggle that is on), `data-checked`, `data-selected`, `data-highlighted` (the keyboard/pointer cursor in a list), `data-invalid`, `data-dragging`, `data-side`/`data-align`, and `data-starting-style`/`data-ending-style` for enter and exit (exit styles go on `data-ending-style`; the part stays mounted until they finish). Read a part's page for its exact list. The react-aria names (`data-hovered`, `data-focus-visible`, `data-focused`, `data-entering`, `data-exiting`, `data-placement`, `data-pressed` for a held press) are gone.
5. **Exact metrics.** The text-scale tokens set font-size only, so they never change a line-height. Keep the original easing (`ease-ios` = `cubic-bezier(.32,.72,0,1)`), radii, shadows and durations; a value that is not on a token scale stays literal until the scale is extended on purpose. `font-family: inherit` is `[font-family:inherit]`.
6. **CSS files** hold only what utilities can't express (keyframes, scrollbars, range thumbs, third-party overrides). The package's `src/styles.css` pulls in the Tailwind token map (`packages/ui/src/tokens.css`) and Tailwind's utilities layer; `src/theme.css` is the optional bl-theme (`@brett_lamy/ui/theme.css`) — no preflight, so host apps keep their base styles.
7. **Core vs blocks.** A part goes in core if it is generic and composes with others; a part that only makes sense inside one product goes in that block. Core modules import only `react`, npm packages, and each other by alias (`@/components/ui/<x>`, `@/lib/<x>`) — never `@brett_lamy/ui` and never a block. Block files import only `react`, `@/components/ui/*`, `@/lib/*`, their own files and the npm packages in their `meta.json` (`node tools/registry/build.mjs --check` fails otherwise). Demo data and compositions live in blocks, docs examples or stories. A file in `lib/` can't be named after a component: shadcn's CLI goes by a file's last path part when it installs, so `@/lib/x` beside `components/x.tsx` becomes `@/components/ui/x`, and the part imports from itself. Call it `lib/x-model.ts`; the registry build refuses the other.
8. **Barrel.** `packages/ui/src/index.ts` re-exports the public API for the npm package, named exports only; every registry manifest's `exports` must be in it (checked). Module internals stay out of it: an export no caller outside the module needs is not exported (`pnpm knip` reports one that is).
9. **Client modules.** A module that uses hooks, `createParts` or motion starts with `'use client'` (`node tools/codemod/use-client.mjs` adds it) so both the package and the copied source work in Next.js server components. A recipe that a server-safe module (Card, Badge, EmptyState) needs lives in a hook-free module (`lib/surface.ts`), never in a `'use client'` one.

10. **Responsive by container, never by viewport.** Shells size themselves from their own box, so a phone frame, a window or a split column behaves like a small screen. A container measures its size class (`compact` / `medium` / `regular`) with `bindSizeClass` from `lib/size-class` (or `useSizeClass()`), which writes `data-size-class` on it for CSS (`group-data-[size-class=compact]/x:`), and provides it to what it renders with `<SizeClassProvider value={sizeClass}>` from `lib/container`: that React context is the size-class scope (`useSizeClassScope()` reads it). `BLProvider`'s root, `SplitView`, `NavigationStack`, `SidebarProvider`, `ArtifactChatContainer` and `SqlConsole` are scopes. Anything that can change presentation takes `presentation`, and its `"auto"` resolves from the scope (`usePresentation`): `Dialog` (its default), `AdaptivePane` and `Sidebar` (theirs too), and the popup wrappers (`Popover`, `DropdownMenu`, `Select`, `Combobox`, `DatePicker`, `ColorPicker`, `FontPicker`) before they pass it to UI SDK — a sheet in a compact scope, their own presentation in a medium or regular one, UI SDK's own rule outside every scope. Context crosses portals, so what counts is where the popup is written, not where it renders. Layers are contained in their host: an element that renders `data-layer-host=""` in its markup (never from an effect) and has `contain: layout` (`[contain:layout]`). `BLProvider`'s root, `<Sheet contained>`'s host (`[data-slot=sheet-host]`) and `FloatingSheet`'s root are hosts, and the kit's popups render into the nearest `BLProvider` root (`useLayerHost()`), so a dialog in a framed app covers the frame, not the page.
11. **Agent-ready and tested.** Every control has a name (a label part or `aria-label`). A component with behavior has a vitest file in happy-dom (`// @vitest-environment happy-dom`) that covers its keyboard, focus and ARIA contract, with `globalThis.__UI_SDK_STRICT__ = true` so UI SDK's development warnings fail the test.

## Design rules

6.0 merged 117 modules into 99 and gave every concept one name. These rules keep it that way.

12. **Consolidate before you add.** A new component, prop or recipe must say, in its pull request and at the top of its docs page, why it is not a `variant`, a part or a documented composition of an existing one. The owner's rule: if a component can be consolidated with another through a composable shared API, it is. The merges so far are the pattern: Credenza is `Dialog` with `view`, SideDrawer is `AdaptivePane`, EdgeDrawer is `<Sheet contained>`, TabView and TabBar are looks of `Tabs`, ContextMenu is `DropdownMenuContextTrigger`, EditBar is `<Toolbar variant="bar">`, SchemaTree is a `Tree` over `schemaTreeItems`, ResultTable is `DataTable`, FloatingChat is `ArtifactChatContainer layout="floating"` on a `FloatingSheet`. Nothing is renamed or removed with an alias or a deprecated re-export: change the call sites. Pairs that were weighed and kept apart (Segmented and Tabs, Select and Combobox, Popover and HoverCard and Tooltip, AlertDialog and Dialog, Sheet and FloatingSheet, Sidebar and SplitView, MarkdownEditor and MarkdownView, and the rest of the design log's list) stay apart unless that decision is reopened.
13. **One spelling per concept.** Use these names, and no synonyms:

    | Concept | The one spelling |
    | --- | --- |
    | size | `size: 'sm' \| 'default' \| 'lg'` (never `md` or `compact`). Extra steps only where documented (Button `pill`, `icon-sm`, `icon`, `icon-lg`; ProgressRing `xl`); raw px numbers only on Avatar, Spinner, ProgressRing. Heights: buttons 32 / 36 / 44, fields 32 / 44 / 50; no others |
    | look | `variant`. An outline look exists wherever a filled one does. A boolean that picks a look is a variant |
    | semantic color | `tone: 'default' \| 'success' \| 'warning' \| 'destructive'` (+ `muted` where a quiet fill exists). Badge keeps shadcn's `variant` |
    | caller color | `tint` (a CSS color) |
    | color scheme | `appearance: 'auto' \| 'light' \| 'dark'` |
    | where | `side` and `align` (`'start' \| 'end'` on the inline axis). Never `position`, `placement`, `left` / `right` |
    | density | `density: 'compact' \| 'default' \| 'comfortable'` |
    | busy | `pending` = an action in flight (writes `data-pending`); `loading` = data not here yet |
    | invalid | comes from `Field`; a control has its own `invalid` only when it can't be a Field control. Error text is a `FieldError`, never an `error` prop |
    | presentation | `presentation`, with `'auto'` wherever a component can change presentation; `auto` resolves from the size-class scope |
    | inset-grouped card | `variant="inset"` (List, Listbox, DisclosureGroup); Separator's indent stays `inset` |
    | an item was activated | `onAction(value, details)`; a single pressable keeps `onClick` |
    | current location | `current` (writes `aria-current`); a toggle is `pressed`; never `active` |
    | open state | `open` / `defaultOpen` / `onOpenChange(open, details)` |
    | empty collections | `emptyState?: ReactNode`, defaulting to the shared `<EmptyState>`; never `emptyMessage` |
    | row anatomy | `icon`, `title`, `description`, `trailing` |
    | parts | flat `RootPart` exports with UI SDK's suffixes; no dotted statics; no leaked internals in the barrel |
    | control names | `<Kind>Input`, never `<Kind>Field` (`Field` itself is the label / description / error wrapper) |

14. **Flat parts.** A compound component exports each part as its own name, `RootPart`, with UI SDK's suffixes (`…Trigger`, `…Content`, `…Header`, `…Title`, `…Body`, `…Footer`, `…Item`, `…Group`, `…GroupLabel`, `…Separator`, `…Indicator`): `SidebarItem`, `FloatingSheetBody`, `ArtifactChatContainerChat`, `ColorPickerInput`. Never a dotted static (`Sidebar.Item`), never a marker slot read from `children`, and a part renders where it is written.
15. **Shared parts exist once.** Draw these from where they live; never copy their classes:

    | Part | Lives in | Used by |
    | --- | --- | --- |
    | `fieldSurfaceVariants({ size })`: the filled field box (background, radius, heights, focus edge, invalid, disabled) | `components/input.tsx` | Input, Textarea, Select, Combobox, DateInput, DatePicker, ColorPicker, FontPicker, MarkdownEditor (and, through Input, Filter's editors) |
    | `surfaceHeaderVariants`, `surfaceTitleVariants`, `surfaceDescriptionVariants`, `surfaceBodyVariants`, `surfaceFooterVariants`, `closeButtonVariants`, `sheetGrabberVariants` | `lib/surface.ts` (hook-free; re-exported by `dialog` and `sheet`) | Dialog, Sheet, AdaptivePane, Popover, HoverCard, Toast, Card |
    | `DialogBack`, `DialogView`, `SurfaceFlow`, `SurfaceFlowTitle`: a flow of views with a back button and a travelling title | `components/dialog.tsx` | Dialog, Sheet (`SheetView`), VaultEnrollDialog |
    | `sectionLabelVariants({ variant: 'grouped' \| 'sidebar' \| 'menu' })` | `lib/primitives.ts` | List sections, FieldLegend, Listbox / Select / Combobox / DropdownMenu / CommandMenu group labels, SplitViewSection, SidebarSection |
    | `barSurface` (the iOS bar: `h-bar`, `bg-bar`, blur, hairline) | `lib/primitives.ts` | Toolbar `bar`, Tabs `bar`, NavigationStack's bar |
    | `focusRing`, `pressableFocusRing`, `dataRowLayers`, `popoverSurface`, `popoverSheet`, `tableHeaderCellClass`, `columnResizerClass`, `valueChip` | `lib/primitives.ts` (internal) | every pressable; LogList, DataTable, RequestTable; every popup; DataTable and Spreadsheet; Combobox and FontPicker chips |
    | `EmptyState` (`icon`, `title`, `description`, `action`, `size`) | `components/empty-state.tsx` | the default of every `emptyState`; ConversationEmpty, CommandMenuEmpty, ComboboxEmpty and the vault's screens compose it |
    | Tree's row: `treeRowVariants`, `TreeItemIndicator`, `renderRow` | `components/tree.tsx` | Tree, ObjectTree, CallStack, the SQL console's schema |
    | `Swap` (`effect: 'slide' \| 'pop'`) | `components/swap.tsx` | Dialog and Sheet views, the composer, the command menu |
    | the segment track: `segmentTrackVariants`, `segmentItemVariants`, `segmentIndicatorVariants`, `segmentIndicatorSlide` | `components/segmented.tsx` | Segmented, Tabs `segmented`, ToggleGroup `filled` |
    | `Toolbar`, `ToolbarButton`, `ToolbarGroup`, `ToolbarSeparator`, `ToolbarText` | `components/toolbar.tsx` | DebugToolbar, the edit bar, Filter, PencilToolbar, VideoPreviewControls |
    | `DataTable` | `components/data-table.tsx` | RequestTable, the SQL console's results and history |
    | `useHideOnScroll` | `lib/scroll-edge.ts` | FloatingSheet (and through it ArtifactChatContainer's floating chat) |
    | `useKeptChildren`, `useCopy`, `usePaced`, `useTriggerPalette` | `lib/kept-children.ts`, `lib/use-copy.ts`, `lib/use-paced.ts`, `lib/trigger-palette.ts` | Sheet and Sidebar; every copy button; ObjectTree and CallStack; menus and popovers with `palette="trigger"` |
    | file icons (`FileTypeIcon`, `FileBadgeIcon`, `FolderIcon`), option rows, shortcut text, the wave rail, the bar's back button | `lib/file-icons.tsx`, `lib/option-row.tsx`, `lib/shortcut-text.ts`, `lib/wave-rail.ts`, `lib/nav-bar.tsx` | Tree; Listbox / Select / Combobox; menus, Tooltip, CommandMenu; IndexBar and TraceTimeline; SplitViewHeader and NavigationStackBar |

    A look two components share becomes one of these before the second copy lands; a new one gets a row here.
16. **Docstream shims.** A Docstream widget the kit documents (`replay-preview`, `tui-preview`, `stl-viewer`, `strudel-player`) keeps exactly one thin `components/` module that re-exports the component, its props and handle types, and the functions a caller needs to drive it. Parsers, helpers, sub-systems and demo data are imported from `@brett_lamy/docstream/*` directly by whoever needs them (a block may: it lists the package in its `meta.json`). Never widen a shim's re-export list.
17. **Registry manifests are hand-written and must match the code.** `registry/components/<name>.json` (shape: `registry/components/types.ts`) is written by the module's owner: its `exports`, `imports`, `types`, `description` and `page` say what the module really exports and does. A new module adds one, a removed module deletes its own, and `node tools/registry/build.mjs --check` fails when they drift. `registry.json` and `registry/dist` are generated from them.
18. **Every component has a docs page and stories.** A component module has a page in `apps/docs/pages/<page>.md` (with a `nav.json` entry; a part can share its root's page) that opens with what it is for and when to use a sibling instead, then usage, props tables, data attributes and accessibility; the page's "Installation" and "## cva recipes" sections are generated (`tools/docs/install-md.mjs`, `tools/docs/variants-md.mjs`) from the manifest and the source, so leave them alone. It has a `*.stories.tsx` beside it with a story per meaningful variant, a dark story and a compact (phone-sized) one for anything responsive.

## The fork

`vendor/ui-sdk` is our fork of UI SDK. `node tools/ui-sdk/build.mjs` (run by `postinstall` when the fork changed) compiles `packages/core` and `packages/react` into `packages/ui-sdk-core` and `packages/ui-sdk-react`, which publish as `@brett_lamy/ui-sdk-core` and `@brett_lamy/ui-sdk-react` and are imported everywhere as `@ui-sdk/core` and `@ui-sdk/react` (npm aliases). The wrappers' `package.json` files are generated; don't edit them.

The fork is upstream (`vercel-labs/ui` at `724a7d6c`) plus three small additions, all `@experimental`, which we mean to propose upstream:

- **Layer hosts.** An element with `data-layer-host` keeps the popups rendered inside it in its box: out of the top layer, placed against its box, modal to it alone (inert, presses, focus, Escape and shortcuts stay inside it), with its own modal stack. No new export: the attribute is the contract, and the host's `contain: layout` is ours to write. Core can't be asked for this from outside: it changes how its popups, layers, positioning, modality and shortcuts work.
- **A `when?: () => boolean` option on the public `bindLayer`**, and `bindLayer` keeping to a host. While `when()` returns false the layer is skipped and Escape goes on to the layer beneath. `lib/stack.ts` builds on it.
- **The kernel type `SlotProps`, exported** from `@ui-sdk/core/renderer` (beside upstream's `BaseSlotProps`), so the library can emit declarations for the primitives it exports.

Nothing else. Keep it that way: an addition goes in the fork only when a component here needs it, it is generic, and it can't be built on UI SDK's public API; anything that can is a behavior in `lib/` (tech rule 2), and anything specific to this library stays in this library. A UI SDK bug is worked around in the kit, recorded with the smallest upstream change on the docs' "Built on UI SDK" page, and reported upstream; the fork doesn't carry fixes. An addition follows the fork's own `contributing/` guides: jsdom tests, a playground fixture and browser spec when it touches popups, pointer or focus code, a changeset, `@experimental`, a `Modified in BLamy/ui-sdk:` line at the top of every file changed from upstream, and a row on that page.

## Checks — run before every commit

- `pnpm vr --project stories` (Storybook on :6006) and `pnpm vr --project docs` (docs dev server on :4417): every screenshot must match its baseline exactly. Inspect a failure with `node tools/vr/zoom.mjs <story-id>` (expected left, actual right). Only re-baseline (`pnpm vr:update`) for an intended visual change, and say why in the commit.
- `pnpm nx run-many -t typecheck,build,test`, `node tools/registry/build.mjs --check`, `node tools/tokens/build.mjs --check`, `node tools/tokens/check.mjs`, `node tools/docs/install-md.mjs --check`, `node tools/docs/variants-md.mjs --check` and `pnpm knip`.

## Storybook (apps/catalog)

Stories live next to components: `packages/<pkg>/src/**/*.stories.tsx`. Use CSF3 with `Meta`/`StoryObj`. Titles follow **atomic design**:

- `Atoms/…` — Icon, Avatar, Button, Toggle, Switch, Segmented, Spinner, SearchInput, Swap, ThemeScope…
- `Molecules/…` — ListRow, IndexBar, Toolbar, DebugToolbar, Filter, Composer… (block parts keep their ids too: Message, ThreadPreview)
- `Organisms/…` — List, NavigationStack, Dialog, Sheet, AdaptivePane, Sidebar, Tree, DataTable, Conversation…
- `Templates/…` — the container layouts that stay in core (SplitView layouts, ArtifactChatContainer…).
- `Blocks/…` — registry blocks (`registry/blocks`), including their own parts (ChatShell, WorkbenchShell, terminal, surfaces, MapChat, DeliveryTracking, PencilKit sketch).

Wrap every story in `BLProvider` (or `ThemeScope`) (use a decorator; dark for the chat and workbench parts). Give container stories an explicit sized frame (e.g. 390×720 phone frame or 100%×640 panel) since BL UI containers are absolutely-positioned within their host. Include a story per meaningful prop/composition variant, with `args` wired so controls work.

## Apps

The workspace has two apps: `apps/docs` (the documentation site) and `apps/catalog` (Storybook). Apps and blocks import through the same aliases a registry install creates (`@/components/ui/<x>`, `@/lib/<x>`, `@/components/blocks/<slug>/…`), configured in `tsconfig.base.json` and `tools/alias.mjs` — this proves that a copied item works in a plain app.
