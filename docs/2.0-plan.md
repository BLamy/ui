theme (`bl-theme`); Workbench and chat become theme *scopes*; cva everywhere; duplicate parts consolidated;
chat/T3-only parts move into their blocks. Today's look must be preserved with `bl-theme` loaded — every pixel
change is listed in "Intentional visual changes" at the end.

## 2. The color system in 2.0

### 2.1 Layers

1. **`packages/ui/src/tokens.css`** (was `theme.css`; compiled into `@brett_lamy/ui/styles.css`): `@theme inline` registering
   every color utility as `--color-x: var(--x)`. Standard shadcn names map straight through (no `--bl-*` indirection).
   The extra tokens (below) map with a fallback derived from shadcn vars, so without `bl-theme` a component still
   renders in the host app's palette (`--tertiary-foreground` falls back to `muted-foreground` at 60%, etc.).
   Also `@custom-variant dark (&:where(.dark, .dark *))` so `dark:` follows the `.dark` class like shadcn apps.
2. **`packages/ui/src/theme.css` → `@brett_lamy/ui/theme.css`** — the **bl-theme**: `:root, .light { … }` and `.dark { … }`
   set every shadcn var (+ extras, chart-1..5, sidebar-*) to the iOS palette; plus the scope rules (2.4). Also a
   registry item `bl-theme` (`registry:theme`, `cssVars.light/dark` + `css` for the scopes). Optional: without it,
   components use the app's shadcn theme.
3. **Providers** only choose *which* values apply: `BLProvider` puts `light`/`dark` on its root (and `--primary`/`--ring`
   inline when `tint` is given); `ThemeScope` (new) puts `data-theme-scope="workbench|chat|terminal"` + `light|dark`.

style) rather than new tokens. Shadows use Tailwind's `black/NN` (`shadow-black/28`) — no palette token.

### 2.4 Theme scopes (in bl-theme)

`ThemeScope` (new; `WorkbenchTheme` = `ThemeScope scope="workbench"` kept as a convenience) renders
`<div data-theme-scope="…" class="light|dark">` and sets `--primary/--ring` inline when `tint` is passed.
`WorkbenchShell`, `ChatShell`, the Workbench terminal (always dark) and `Sidebar` examples use it. bl-theme defines:

- `[data-theme-scope=workbench]` (light) / `[data-theme-scope=workbench].dark` — the old `workbenchVars()` values.
- `[data-theme-scope=terminal]` — always dark; background #0C0C10, or #1A1A1F inside a light Workbench.
- `[data-theme-scope=chat]` / `.dark` — the old `chatTokens` / `chatLightTokens`.

Without bl-theme a scope is just `light|dark` → the app's own `:root` / `.dark` palette.
Portalled popovers copy the resolved variables of their trigger (`readThemeVars`, replaces `readWbTokens`).

`--gb-*` (docstream) is mapped once, in styles.css `.wb-md`/`.bl-mde`/composer rules, from shadcn vars only.

### 2.5 Removed exports

`blLightVars`, `blDarkVars`, `workbenchVars`, `workbenchAppearanceClass` (→ `themeScopeClass`), `chatTokens`, `chatTokenVars`,
`chatLightTokens`, `chatLightTokenVars`, `chatVars`, `K`, `ChatTokens`, `sidebarDarkVars`, `readWbTokens` (→ `readThemeVars`),
`PK_LIGHT`, `PK_DARK`, `KFONT/KMONO/KEASE`, `WFONT/MONO/PFONT/PMONO` (→ `FONT`, Tailwind `font-ios`/`font-mono`).

## 4. cva / inline-style work

- Components with variant-like props that don't use cva yet get `…Variants` + `VariantProps` in their props.
- `style={{…}}` stays only for runtime values (gesture offsets, measured sizes); everything static moves to utilities.
- Literal colors: none in components/demos except named content constants (map tiles, artwork, PencilKit inks
  `PK_INKS`, syntax palettes, user role colors in fixtures).

## 5. Blocks impact

All 9 blocks use `bl-*` utilities (github-clone 237) and several set `--bl-*` inline palettes (github-clone's own
light/dark palette, apple-notes `--bl-on-tint`). Phase 3 (after the blocks refactor merges): rewrite to shadcn
utilities; per-block palettes become scope classes or plain utilities with opacity modifiers; discord-clone absorbs
the chat parts, t3-clone the ThreadSidebar parts. Until then `tokens.css` keeps a *temporary* `bl-*` utility compat
map (removed in phase 3).
